## Contexto
Segundo día del port a TypeScript (MEF-ADR-0057). Se trabajó en lotes: un worktree por lote bajo `.mefisto/worktrees/`, un agente que entrega commits locales y un PR por lote, verificado con `tsc`, `node --test` y el workflow `typescript.yml` en sus seis celdas antes de mergear.

## Descubrimientos
- Los bloques de bash que Claude ejecuta desde comandos, agentes y skills (unos 350, con 96 usos de `jq`) no se pueden portar a TypeScript: en Windows nativo, Claude Code usa Git Bash para la herramienta Bash si Git for Windows está instalado y, si no, PowerShell.
- Un test que extrae un bloque de bash del markdown y lo ejecuta no se puede portar mientras el bloque sea bash: quedó como residual hasta el paso 7.
- La paridad con `jq` no puede depender de su versión: jq 1.7 y 1.8 difieren (p. ej. `tonumber` sobre una cadena con espacios) y los runners de CI traen versiones distintas.
- Las librerías grandes (`_pipeline-common.sh`, `_mefisto-common.sh`) se portaron primero como gemelas TypeScript, función por función, con un test de paridad contra la función bash real que se salta en Windows.
- `tooling-pipeline` (#2599) se convirtió en el modelo de los demás pipelines: dejó en `scripts/lib/pipeline/` los módulos comunes (cierre único en éxito, aborto, excepción y señal; log; status; reintentos con espera por límite de uso y reanudación; worktree; PR). Las diferencias entre pipelines entran como parámetros.
- En Windows el runner termina al agente con `taskkill /PID <pid> /T /F` sobre el PID que lanzó; nunca mata por nombre.

## Decisiones
- Decisión del usuario: en Windows se exige Git for Windows (#2584, MEF-ADR-0057 decisión 9). Los bloques de bash del markdown se quedan en bash y corren en Git Bash; solo se reemplaza lo que Git Bash no trae: `jq` y `python3` pasan a `node scripts/json-value.mts` (#2596). Los scripts del harness no dependen de bash.
- El preámbulo que fija `MEFISTO_PACKAGE_ROOT` valida la raíz con `verify-package-root.mts` y acepta raíces de Windows (#2598).
- Los defectos que ya tenía el bash se portan tal cual y van a borradores (#2571, #2572, #2576, #2579, #2581, #2589, #2591, #2600), salvo que en Windows rompan algo.
- Paso 5 cerrado (#2559 a #2586): scripts sueltos publicados e internos, los dos generadores, sus validadores y el gate de neutralidad; MEF-ADR-0049 y 0050 dejaron de fijar bash + `jq` como toolchain del generador.

## Descartado
- Reescribir en TypeScript los bloques de bash del markdown o pasarlos a PowerShell.
- Corregir de paso los defectos heredados del bash dentro de los lotes de port.

## Preguntas abiertas
- `field-note` valida el glosario YAML con un validador del PATH (`python3` con PyYAML, `ruby` o `yq`); en Windows sin ninguno aborta con mensaje.
- Ningún script portado se ha probado contra Azure, GitHub ni `claude` reales: los tests inyectan esos CLIs.
- `mefisto-release.mts` no se ha ejecutado contra el repo real: el primer release que lo use es su prueba de extremo a extremo.
