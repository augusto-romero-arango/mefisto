## Contexto
El objetivo es que Mefisto funcione completo en macOS y Windows nativo, solo con Claude Code; Linux se verifica en CI. bash + jq + python3 + tmux no corren en Windows nativo. El trabajo se hizo fuera de los pipelines de Mefisto (sin issues ni `/mefisto-plan`), con un goal por paso y el avance en `docs/portabilidad/ESTADO.md` (#2546).

## Descubrimientos
- Un `.ts` ejecutado con type stripping falla si una carpeta superior tiene `package.json` con `"type":"commonjs"`: de ahí la extensión `.mts` para todos los módulos.
- Claude Code acepta hooks en forma exec (`command: "node"` más `args`, sin shell), lo que deja los 7 hooks publicados sin depender de bash.
- En Windows, git entregaba CRLF y rompía los shims y las lecturas de texto: el repo fija LF con `.gitattributes` (#2561, #2562), y el registro de esa ruta en los gates de scope tuvo que ir en un PR previo.
- `az` en Windows es `az.cmd`: la utilidad de procesos lanza los `.cmd`/`.bat` a través de `cmd.exe` (#2565).
- Para comparar rutas en Windows hay que usar `realpathSync.native`: la variante JS no expande los nombres cortos 8.3 y el workflow falló por eso.

## Decisiones
- MEF-ADR-0057 (#2547): los scripts bash se portan a TypeScript sobre Node >= 22.18, ejecutado directo (`node x.mts`), sin build ni dependencias npm en ejecución; tmux se retira del todo (quedan herdr y el modo desacoplado); se conserva herdr; OpenCode sale y Claude Code queda como runtime único, conservando el contrato de eventos JSONL, la interfaz de runtime y la fuente neutral `src/internal/`; el port es incremental sobre `main`, con bash y TypeScript conviviendo.
- Orden: primero retirar OpenCode (#2551, #2552), luego tmux (#2555), porque sin OpenCode el único uso de tmux que quedaba era el modo explícito.
- Base TypeScript (#2556): `src/internal/tsconfig.json`, workflow `typescript.yml` en macOS, Linux y Windows sobre Node 22.18 y 24 (excepción acotada a la política de no correr tests en PRs), y el medidor `mefisto-portability-status.mts` con las métricas M1 a M6.
- Hooks (#2557, #2558): los publicados y el de scope interno pasan a TypeScript; con ellos entra el requisito de Node >= 22.18 para el consumidor, que `/onboard` comprueba.
- Cada script se porta completo con sus tests en un PR; su `.sh` queda como shim (`exec node x.mts`) mientras tenga llamadores en bash.

## Descartado
- Evaluar Pi u otro runtime como segundo harness: no hay segundo runtime en los planes.
- Una rama larga de "nueva versión": el port va incremental sobre `main`.
- Gestionar el port con issues y `/mefisto-plan`.

## Preguntas abiertas
- El hook `pre-push` se queda en shell porque lo ejecuta Git; falta confirmar que corre con Git para Windows (W6).
